# M5 adverse-condition audit

Audit dates: 2026-09-22 through 2026-09-23. All device observations below used the physical Pixel
8a / Android 17. RF cases used the project HackRF One in receive-only mode;
debug fault controls exercised production recovery branches on that hardware
and are identified explicitly. No emulator or mocked radio result is presented
as hardware evidence.

| Condition | Direct evidence and disposition |
| --- | --- |
| USB detach and reconnect | The M1 physical run removed the HackRF during an active survey, surfaced `USB detached; gap recorded`, drained all queues, required fresh permission, resumed after reconnection, and finalized a closed `USB_DETACH` gap. A second readback recorded a 92,201 ms gap and complete survey. The M5 signed-release survey independently paused at physical detach with 104,000 persisted observations, zero drop/overrun/malformed counts, and two closed detach rows in the validated export. See [M1 hardware report](../M1/hardware-report.md) and [field report](field-report.md). |
| Process interruption | The application was force-stopped during physical HackRF acquisition, relaunched, recovered the same survey, resumed RX, and later finalized it with a persisted 47,867 ms `PROCESS_DEATH` gap. See [M1 hardware report](../M1/hardware-report.md). M5 keeps durable state Active/Paused until RX has stopped and every queue has drained/accounted, so a kill during draining recovers with a gap instead of falsely completing; connected Room coverage completes only a genuinely persisted `FINALIZING` state idempotently. |
| Low storage | `BoundedPipelineTest.storageGuardPreservesFixedReserve` and `CaptureContractsTest.preflightEnforcesDurationThroughputAndStorageReserve` reject survey/capture work before allocation when required bytes plus reserve are unavailable. On the Pixel with the HackRF active, a debug-only control invoked the production active-service low-storage branch; the survey stopped orderly as `COMPLETE` with a closed `LOW_STORAGE` gap and no drops, overruns, or malformed frames. This is controlled fault injection, not a claim that the phone disk was filled. See [M1 failure injection](../M1/failure-injection.md). |
| Queue pressure / overruns | Capacity-one unit tests prove every rejected native, processing, and persistence unit is attributed to its stage. A physical 34:42 screen-off run persisted and surfaced three real native overruns; the later 32-buffer gate completed 31:04 with zero drops/overruns. The application never hides or silently clears either result. |
| Battery saver and screen off | The M5 field run retains a continuous 35:27 screen-off interval with the foreground notification and GNSS activity present. Battery decreased from about 64% to 56% and no thermal warning was recorded. See [screen-off evidence](screen-off-evidence.md). |
| Thermal pressure | `BoundedPipelineTest` exercises the production thermal warning/stop policy and verifies settings are not silently changed. Physical runs recorded thermal status 0. The milestone explicitly permits a safe synthetic equivalent; the HackRF and phone were not deliberately overheated. |
| Location degraded / recovered | Physical surveys retained missing, stale, unlocated, and accuracy-bearing GPS states without invented coordinates; the 31:04 gate retained 1,854 fixes and 2,340 explicitly unlocated observations. During the M5 signed-release survey, the real Android location setting was disabled: at 1:44 the UI surfaced a 79-second-old fix and 27,040 persisted aggregates. Re-enabling location produced a fresh 49.0 m fix at 2:19 and 36,140 aggregates, with zero loss counters throughout. `LocationAssociationTest` covers freshness, interpolation, and bounded-gap rules. |
| Permission denial / revocation | Pixel tests revoked coarse and fine location permission and verified the foreground receive service ended in an explicit error without crashing. Physical HackRF detach/reconnect separately exercised USB permission reacquisition and the visible `PERMISSION_REQUIRED` branch. |
| Offline map / network loss | The Pixel downloaded 309 resources (8,639,752 bytes), then with airplane mode enabled and Wi-Fi disabled reopened the cached region and local relative-strength overlay with attribution. See [M3 offline behavior](../M3/offline-behavior.md). |
| Capture interruption | `CaptureContractsTest` covers cancellation, callback failure, write failure, and short delivery; only a complete IQ/sidecar/preview set is committed. `InterruptedArtifactRecoveryTest` and connected `NotebookDatabaseTest.interruptedCaptureCommitIsRecoveredOrFailedWithoutUnindexedArtifacts` cover temporary cleanup and the durable `CAPTURING`-to-`COMPLETE`/`FAILED` recovery boundary. The final physical capture completed with zero capture gaps/overruns and passed sidecar/hash validation from both exported archives. |
| Export/import interruption | Export is written to `.part`, fully closed, and atomically replaces a prior archive only when the filesystem supports atomic replacement. Rejected imports remove their incoming cache ZIP and never partially commit a destination. Hostile path, size, compression-ratio, schema, hash, and symlink cases are rejected. M5 added bounded strict streaming validation for every required manifest field/type, unknown or duplicate properties, file records, and inclusion flags. A physical Android ICU regex crash during redacted sidecar export left the authoritative capture intact; structured JSON replacement plus an Android 17 regression fixed it. Corrected full and redacted exports both passed manifest/hash inspection and release-app reimport. |
| Corrupt database | A connected Room test writes a non-SQLite database, verifies startup fails closed, and verifies the original bytes remain unchanged. There is no destructive fallback migration. |
| Corrupt/hostile archive | `SurveyBundleTest` covers missing manifest, unknown schema, checksum mismatch, duplicates, traversal, absolute paths, unsupported entries, oversized entries, excessive entry count, compression bombs, and symbolic links. The committed M4 fuzz corpus passes `Test-M4Schemas.ps1`. |

The cases above cover the adverse-condition matrix without weakening the
product invariants. Controlled failure injection is used only where creating
the literal condition would be unsafe or destructive; it does not substitute
for physical USB, RF, screen-off, GPS, process, or offline-map evidence.
